## Balinet Mandatory Safety Tests

### Secrets
- Search tracked and deployable files for API keys, passwords, private tokens, and credentials.
- Confirm secrets are loaded from protected configuration.
- Confirm logs and error messages do not expose secrets.

### Authorization
- Test every privileged endpoint without authentication.
- Test it with the wrong role.
- Test direct URL and API access even when the UI hides the action.

### User and tenant isolation
- Create or use two separate test users/workspaces.
- Attempt to fetch, update, and delete the other user's records by changing IDs.
- Confirm all unauthorized attempts fail server-side.

### Error tracking
- Trigger representative application failures.
- Confirm a useful error is logged.
- Confirm users receive a safe, understandable message.
- Confirm logs do not expose sensitive data.

### Backup and restore
- Create a backup.
- Change or remove a test copy of a file or record.
- Restore from backup.
- Verify checksum, content, permissions, and application behaviour.

### Critical-screen regression
- Capture and compare the five most important screens or workflows.
- Test desktop and mobile where applicable.
- Review console, network failures, broken assets, and visual regressions.

### Root-cause closure
- Record the cause, evidence, fix, validation, and prevention measure.
- Do not close a defect using syntax validation alone.
